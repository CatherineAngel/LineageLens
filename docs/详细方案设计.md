# SQL 血缘 VSCode 插件 — 详细方案设计

> 基于 sqlglot 引擎，支持多 SQL 方言显式选择
> 日期：2026-11-18 · 基于 sqlglot 30.33.0 实测

---

## 0. 设计原则

1. **引擎在 Python，壳在 TS** — sqlglot 只负责"SQL → 血缘图"，VSCode 集成、增量调度、渲染全在 TS 侧。
2. **方言显式选择** — 不做自动猜测兜底，用户必须明确当前文件/选区用哪种方言，避免"猜错了还静默给出错误血缘"。
3. **解析失败必须可见** — 任何降级/失败都要在 UI 上标记，绝不允许静默产出空图。
4. **不阻塞 UI** — Pyodide 跑在 worker 线程里（实测暖机后单次调用 0ms）。

## 一、方言选择机制（核心需求）

### 1.1 为什么必须显式选择

同一个 SQL 在不同方言下语义不同，且 sqlglot 方言之间**不会自动回退**：

```sql
SELECT id FROM t WHERE dt = '20240101' LIMIT 10
-- hive / mysql 都能过，但 GaussDB 的 DISTRIBUTE BY 只有 postgres 认
```

实测：`CREATE TABLE t (id bigint) DISTRIBUTE BY HASH(id)`
- `postgres` 方言 → 降级为 `Command`（AST 丢失）
- 其他方言 → 直接报错

如果靠猜，用户会得到一张"看起来成功但实际错误"的图，比报错更危险。

### 1.2 三级方言来源（优先级从高到低）

| 优先级 | 来源 | 示例 | 说明 |
|---|---|---|---|
| 1 | **当前选区/命令显式传参** | 右键 → "分析血缘（Hive）" | 单次覆盖 |
| 2 | **文件级标记** | 文件头 `-- dialect: hive` | 随文件走，可提交到 git |
| 3 | **工作区配置** | `sqlLineage.defaultDialect` | 全局默认 |
| 4 | **语言模式映射** | VSCode 语言 ID → 方言 | 兜底 |

**注意**：不提供"自动检测"。可以在状态栏显示当前方言并提供一键切换，但不猜。

### 2.1 为什么用 Worker + Pyodide

实测数据（Node 24，Apple Silicon）：

| 场景 | 耗时 |
|---|---|
| Pyodide 首次启动（worker 内） | ~3.0–5.4 s |
| sqlglot 安装（首次，走缓存后） | 首次 ~5.9 s |
| **暖机后单次列级血缘** | **0 ms**（<1ms） |
| 8199 行 / 200 语句全量解析 | 137 ms |

结论：冷启动必须放到后台，且绝不能跑在主线程（否则扩展宿主卡死）。

启动策略：
```ts
// activate() 时立即预热，不等用户触发
engine.startInBackground();

// 用户触发时如果还没 ready，UI 显示
// "血缘引擎加载中 (1/2)..." 并在 ready 后自动继续
```

### 3.3 语句切分（自己实现，不用 sqlglot 的）

`sqlglot.parse()` 按 `;` 切分，但**不保留位置信息**。需要自己切分以获得每条的起止 offset：

```python
def split_statements(sql: str) -> list[StatementSlice]:
    """按 ; 切分，跳过字符串字面量、注释、以及 $$ ... $$ 块。"""
```

状态机实现（复用你 `lint_dws_sql.py` 里 `mask_non_code()` 的思路）：

| 状态 | 进入 | 退出 | 说明 |
|---|---|---|---|
| CODE | 默认 | — | 正常代码 |
| LINE_COMMENT | `--` 或 `#` | `\n` | 行注释 |
| BLOCK_COMMENT | `/*` | `*/` | 块注释（支持嵌套） |
| SINGLE_QUOTE | `'` | `'`（`''` 视为转义） | 字符串 |
| DOUBLE_QUOTE | `"` | `"` | 标识符或字符串 |
| BACKTICK | `` ` `` | `` ` `` | MySQL 标识符 |
| DOLLAR_QUOTE | `$$` | `$$` | PG 函数体 |

只在 `CODE` 状态下遇到 `;` 才切分。同时记录每条语句的 `(startOffset, endOffset, startLine, endLine)`。

### 3.4 方言预处理补丁

实测确认的必要补丁：

#### GaussDB：剥离 `DISTRIBUTE BY`

```python
# sqlglot postgres 方言不认 DISTRIBUTE BY，会静默降级为 Command
_DISTRIBUTE_RE = re.compile(
    r"\s+DISTRIBUTE\s+BY\s+(HASH|ROUNDROBIN|REPLICATION)\s*\([^)]*\)",
    re.IGNORECASE,
)

def strip_distribute_by(sql: str) -> tuple[str, list[str]]:
    """返回 (改写后SQL, 警告列表)。用等长空格替换，保持所有偏移不变。"""
    warnings = []
    def repl(m):
        warnings.append(f"已剥离 GaussDB 专有语法: {m.group(0).strip()}")
        return " " * len(m.group(0))
    return _DISTRIBUTE_RE.sub(repl, sql), warnings
```

> **关键技巧**：用**等长空格**替换而不是删除，这样 AST 里所有 `start/end` 偏移量都保持有效，位置映射不用重算。

#### MySQL：`REPLACE INTO`

sqlglot 的 mysql 方言不识别 `REPLACE INTO`（实测降级为 `Command`）。改写为语义等价的解析形式：

```python
def rewrite_replace_into(sql: str) -> tuple[str, list[str]]:
    # REPLACE INTO t (...) SELECT ...  →  INSERT INTO t (...) SELECT ...
    # 语义差异（DELETE 后 INSERT）不影响血缘，只影响元数据
    ...
```

同样用等长替换（`REPLACE` 7 字符 → `INSERT ` 7 字符），保持偏移。

#### Oracle：分区 DDL

```sql
CREATE TABLE t (id NUMBER) PARTITION BY RANGE (dt) (PARTITION p1 VALUES LESS THAN (...))
```
实测抛 `Expecting )`。策略：**不强行修复**，标记为 `kind: "ddl_unsupported"`，只在表级图上创建节点、不解析列定义，并给出明确 warning。

#### PL/SQL 匿名块

```sql
BEGIN ... END;
```
直接跳过，标记 `kind: "plsql_block_skipped"`，因为里面通常是动态 SQL（`EXECUTE IMMEDIATE`），静态分析本就无能为力。

### 3.5 血缘提取算法

```python
def analyze_statement(stmt_sql: str, ast: exp.Expression, schema: dict) -> StatementResult:
    # 1. 降级检测（最重要，必须第一步）
    if isinstance(ast, exp.Command):
        return fallback_regex_extract(stmt_sql)  # 正则兜底，只出表级

    # 2. 目标表
    target = None
    if isinstance(ast, exp.Insert):
        target = ast.this  # Table 或 Schema(Table + Partition)
    elif isinstance(ast, exp.Create):
        target = ast.this
    elif isinstance(ast, exp.Merge):
        target = ast.this

    # 3. 源表（scope 遍历，能正确处理 CTE / 子查询 / 派生表）
    sources = []
    for scope in traverse_scope(ast):
        for alias, src in scope.sources.items():
            node = src[0] if isinstance(src, tuple) else src
            if isinstance(node, exp.Table):
                sources.append(SourceTable(
                    db=node.db, table=node.name, catalog=node.catalog,
                    alias=alias,
                    is_cte=(alias in [c.alias_or_name for c in ast.find_all(exp.CTE)]),
                    range=to_range(node.meta),
                ))

    # 4. 列级血缘
    edges = []
    if target and options.includeColumnLineage:
        for out_col in get_output_columns(ast):
            node = lineage(out_col, stmt_sql, schema=schema, dialect=dialect)
            for leaf in walk_leaves(node):
                edges.append(ColumnEdge(
                    target_table=target.name,
                    target_column=out_col,
                    source_table=resolve_alias(leaf),   # 'o.amt' → 'ods.orders'
                    source_column=leaf.split('.')[-1],
                    expression=...,   # 变换表达式
                    transform_type=classify(node),  # direct/aggregate/function/case
                ))
    ...
```

### 3.6 别名 → 物理表 的解析（必须自己补）

实测：无 schema 时 `lineage()` 的叶子节点是 `o.amt`（别名.列），不是 `ods.orders.amt`。

```python
def resolve_alias(leaf_name: str, alias_map: dict[str, str]) -> tuple[str, str]:
    """alias_map: {'o': 'ods.orders', 'p': 'ods.products'}"""
    parts = leaf_name.split(".")
    if len(parts) >= 2 and parts[0] in alias_map:
        return alias_map[parts[0]], parts[-1]
    if len(parts) >= 2:
        return ".".join(parts[:-1]), parts[-1]
    return "<unknown>", leaf_name
```

`alias_map` 从 `scope.sources` 构建（见 3.5 第 3 步）。

### 3.7 位置信息转换（中文/emoji 坑）

实测：sqlglot 的 `meta={"start": 25, "end": 26}` 是 **Python 码点索引**，而 VSCode 的 `Position.character` 是 **UTF-16 code unit 索引**。

```python
def codepoint_to_utf16(text: str, cp_index: int) -> int:
    """码点索引 → UTF-16 索引。BMP 外字符（emoji）占 2 个 code unit。"""
    if cp_index <= 0:
        return 0
    return len(text[:cp_index].encode("utf-16-le")) // 2
```

验证数据：
```
"SELECT 中文别名, amt ... , '😀' AS emoji_col ..."
码点长度:  51
UTF-16 长度: 52   ← emoji 占 2 个
emoji 位置: 码点 25, UTF-16 25（emoji 之前一致）
emoji 之后: 全部偏移 +1
```

**必须在 Python 侧做转换**再返回给 TS，否则 TS 侧拿不到原始文本没法换算。

### 3.8 `Command` 降级兜底

```python
_FALLBACK_PATTERNS = [
    (re.compile(r"\bREPLACE\s+INTO\s+([\w.$`\"]+)", re.I), "replace_into"),
    (re.compile(r"\bINSERT\s+(?:OVERWRITE\s+)?(?:INTO\s+)?(?:TABLE\s+)?([\w.$`\"]+)", re.I), "insert"),
    (re.compile(r"\bCREATE\s+(?:EXTERNAL\s+)?TABLE\s+(?:IF\s+NOT\s+EXISTS\s+)?([\w.$`\"]+)", re.I), "create"),
]
_SOURCE_PATTERNS = [
    re.compile(r"\bFROM\s+([\w.$`\"]+)", re.I),
    re.compile(r"\bJOIN\s+([\w.$`\"]+)", re.I),
]

def fallback_regex_extract(sql: str) -> StatementResult:
    """AST 丢失时的最后一道防线：只出表级血缘，并明确标记 degraded。"""
    return StatementResult(
        kind="command",
        degraded=True,
        warnings=["该语句无法生成 AST，已降级为正则抽取（仅表级）"],
        ...
    )
```

**UI 必须区分三种颜色**：
- 🟢 正常（AST 完整）
- 🟡 降级（`Command` + 正则兜底）
- 🔴 失败（完全无法解析）

## 四、增量与缓存设计

### 4.1 语句级缓存键

```
cacheKey = sha256(sqlglotDialect + "\0" + statementText + "\0" + schemaHash)
```
schema 变了要失效，所以带上 `schemaHash`。

### 4.2 编辑时的流程

```
onDidChangeTextDocument
  → 提取变更范围
  → 找出受影响的语句（按语句 range 判断）
  → 只把这些语句标记为 dirty
  → 防抖 400ms
  → 只把 dirty 语句送给引擎
  → 合并缓存中 clean 语句的结果
  → 重建整图 → 推送 Webview
```

实测支撑：3 语句脚本连续重解析 50 次共 10ms（单次 0.19ms），所以即使退化为"整文件重算"在 200 条以内也可接受（137ms）。**先做简单版（整文件重算 + 结果缓存），再优化增量**。

### 4.3 缓存淘汰

- LRU，容量 500 条语句
- 文档关闭时清理该文档的所有条目
- 方言切换时：不清理（key 里有方言，天然隔离）

## 五、多文件分析设计

### 5.1 文件选择

三种入口：
1. 资源管理器多选 → 右键"分析所选文件血缘"
2. `sqlLineage.include` glob 配置（如 `**/*.sql`）
3. 当前文件 + 它的直接上下游（递归 2 层）

### 5.2 跨文件拼接

关键：**表名是唯一的连接点**。

```ts
// 1. 每个文件独立解析，得到 { target, sources }[]
// 2. 按全限定名建索引
const producedBy = new Map<string, FileResult[]>();  // "dws.t2" -> [fileA]

// 3. 拼接：如果 fileA 的 target 出现在 fileB 的 sources 里，就连一条边
// 4. 用并查集合并同一张表的多个定义（不同文件可能都 INSERT 同一张表）
```

### 5.3 表名规范化（易错点）

用户可能写：
- `t1`
- `db.t1`
- `hive_catalog.db.t1`
- `` `db`.`t1` ``

规范化规则：
```ts
function normalizeTableName(node): string {
  const db = node.db?.toLowerCase() ?? currentSchema;  // 可用配置补全
  const table = node.name.toLowerCase();
  return `${db}.${table}`;   // 统一成 2 段
}
```
**必须在图节点 ID 上用规范化后的名字**，否则 `t1` 和 `db.t1` 会变成两个节点。

### 5.4 跨文件图的视觉区分

| 元素 | 样式 |
|---|---|
| 当前文件产出的表 | 实线边框、高亮色 |

| 交互 | 实现 | 价值 |
|---|---|---|
| 点击节点 | `postMessage` → `TextEditor.revealRange()` | 跳回源码，最核心 |

### 6.5 大图性能保护

实测 200 条语句 = 137ms，但如果一个目录有 500 个文件，节点数会爆炸。

保护策略：
- 节点数 > 200 时默认折叠为表级
- 表级节点 > 500 时提示"结果过大，建议缩小范围"，并只渲染 2 跳内邻居
- 用 React Flow 的 `onlyRenderVisibleElements`

### 9.2 Pyodide + sqlglot 的离线打包（关键）

不能依赖运行时从 CDN 下载（违背离线要求，且企业内网不可用）。

方案：**构建期预下载 + 随插件分发**

```
vendor/
├── pyodide/                  # pyodide 核心（~10MB，可按需裁剪）
│   ├── pyodide.asm.wasm
│   └── pyodide.asm.js
└── wheels/
    └── sqlglot-30.33.0-py3-none-any.whl
```

worker 里：
```ts
const py = await loadPyodide({ indexURL: path.join(extPath, "vendor/pyodide") });
await py.loadPackage(`${extPath}/vendor/wheels/sqlglot-30.33.0-py3-none-any.whl`);
```

体积权衡：
- 完整 Pyodide ≈ 10–12 MB（压缩后 ~5MB）
- sqlglot wheel ≈ 1.5 MB
- **总计约 7MB（vsix 压缩后）** — 可接受，需在 README 说明

替代方案（如体积不可接受）：检测用户机器上的 Python，走子进程 sidecar。可作为 P2 的"高性能模式"。

### 13.2 方言解析优先级

```ts
// src/dialects/resolve.ts
export function resolveDialect(
  doc: vscode.TextDocument,
  explicit?: string,   // 来自命令参数
): DialectSpec {
  // 1. 命令显式指定
  if (explicit) return byId(explicit);

  // 2. 文件头标记
  if (config.fileHeadersEnabled) {
    const head = firstNChars(doc, 2000);
    const m = /^\s*--\s*dialect\s*:\s*([\w-]+)/im.exec(head);
    if (m) {
      const spec = byId(m[1]);
      if (spec) return spec;
      vscode.window.showWarningMessage(
        `文件头方言 "${m[1]}" 未识别，回退到默认方言`
      );
    }
  }

  // 3. 工作区配置
  const configured = byId(config.defaultDialect);
  if (configured) return configured;

  // 4. 语言 ID 兜底
  return byLanguageId(doc.languageId) ?? DIALECTS[0];
}
```

### 13.3 各级状态码约定

```ts
export type ParseStatus =
  | "ok"                  // AST 完整，血缘可信
  | "degraded"            // 预处理/正则兜底，仅部分信息
  | "unsupported"         // 语句类型不支持（如 PL/SQL 块）
  | "failed";             // 完全解析失败
```

绝不允许出现"没有 status 但图是空的"这种情况 —— 所有空图必须对应一个明确的 status。
